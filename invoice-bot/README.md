# LINE請求書読み取りボット（タイ・おにまる）

仕入先が LINE グループに送ってくる請求書（写真・PDF）を読み取り、Googleスプレッドシートに記録するボット。
報告は加藤さんの個別トークにだけ送り、業者のグループでは発言しない。

## 仕組み

1. 業者が LINE グループに請求書を投稿する
2. `doPost`（Webhook）は「キュー」シートに1行書いてすぐ応答する
3. 1分ごとのトリガー `processQueue` がキューを処理する
   - 判定：登録済みのグループ／送信者（空欄なら誰でも）／形式（画像・PDF）
   - LINE から中身を取ってドライブに保存
   - Claude API に画像・PDF をそのまま渡して読み取る（請求書以外は記録しない）
   - 整える（仏暦→西暦、「05」→0.5、品目マスタと照合、配送料は明細に入れない）
   - 検算（各行 ±1バーツ、伝票の合計 ±1バーツ）、重複確認、単価の変動（±20%）
   - 「伝票」「明細」に記録し、OK／要修正ボタン付きで報告
4. OK を押すと、シートの値で検算し直し、合っていれば「確認済み」になる
5. 月次集計・単価履歴・品目マスタの参考単価は、確認済みの伝票から自動で作り直す

## ファイル

| ファイル | 内容 |
|---|---|
| `gas/Main.gs` | doPost（Webhook の受け口）、メニュー |
| `gas/Queue.gs` | キューの処理、判定、ドライブ保存、報告、過去分の一括取り込み |
| `gas/Claude.gs` | Claude API で読み取り |
| `gas/Normalize.gs` | 日付・数量・品目名・配送料を整える |
| `gas/Validate.gs` | 検算・単価変動・重複判定 |
| `gas/Sheets.gs` | 記録、OK／要修正、月次集計、単価履歴 |
| `gas/Line.gs` | LINE の送受信、ボタンの処理 |
| `gas/Config.gs` | シート名・列・設定の読み込み |
| `gas/Setup.gs` | 初期設定（シート作成・トリガー） |
| `gas/Tests.gs` | 実物の伝票で正解データと照合するテスト |
| `test/` | パソコンの Node.js で動かすテスト（Apps Script を使わない部分と、通しの動き） |

価格の実データ（テストの正解・参考単価）は公開しない。`_private/InitialData.gs` に分けてあり、GitHub には上がらない。

## 初めて設定するときの手順（Windows）

コードは GitHub の次の場所にある。各ファイルを開き、右上の「Copy raw file」（四角が2つ重なったアイコン）でコピーできる。
https://github.com/yuya-kato-marino/onimaru-order-app/tree/main/invoice-bot/gas（フォルダ整理の前は、リポジトリの一番上）

### A. LINE 公式アカウント（名前とプロバイダーが決まってから）

1. https://manager.line.biz/ を開き、「作成する」から伝票読み取り専用のアカウントを新しく作る。
   → 成功：アカウントのホーム画面が表示される。
2. 右上の「設定」→ 左の「Messaging API」→「Messaging APIを利用する」を押し、プロバイダーを選んで「OK」。
   → 成功：「ステータス：利用中」と Channel ID が表示される。
3. 左の「応答設定」で、「応答メッセージ」をオフ、「Webhook」をオンにする。「あいさつメッセージ」もオフにする。
   → 成功：応答メッセージがオフの表示になる（オンのままだと、ボットがグループで自動返信してしまう）。
4. 左の「アカウント設定」→「機能の利用」の「グループ・複数人チャットへの参加を許可する」を「許可する」にする。
   → 成功：「許可する」が選ばれた状態で保存される。
5. https://developers.line.biz/console/ を開き、プロバイダー → 今作ったチャネル →「Messaging API設定」タブの一番下「チャネルアクセストークン（長期）」で「発行」を押してコピーする。
   → 成功：長い英数字の文字列が表示される（メモ帳に一時的に貼っておく。人に送らない）。

### B. スプレッドシートと Apps Script

6. https://drive.google.com/ で「新規」→「Google スプレッドシート」を作り、名前を「請求書記録（タイ）」にする。
   → 成功：空のスプレッドシートが開く。
7. スプレッドシートのメニュー「拡張機能」→「Apps Script」を押す。
   → 成功：新しいタブで Apps Script のエディタが開く。左上の「無題のプロジェクト」を「請求書ボット（タイ）」に変える。
8. 左の歯車「プロジェクトの設定」で、「「appsscript.json」マニフェスト ファイルをエディタで表示する」にチェックを入れる。
   → 成功：左の「エディタ」（`< >` のアイコン）に戻ると、ファイル一覧に `appsscript.json` が出る。
9. ファイルを作って貼り付ける。
   - 最初からある `コード.gs` は、名前を `Main` に変える（ファイル名の右の「︙」→「名前を変更」）。
   - 「ファイル」の右の「＋」→「スクリプト」で、`Config` `Normalize` `Validate` `Claude` `Line` `Queue` `Sheets` `Setup` `Tests` を作る（`.gs` は自動で付く）。
   - それぞれ、GitHub の同じ名前のファイルを開いて「Copy raw file」でコピーし、エディタの中身を全部消して（Ctrl+A → Delete）から貼り付ける。
   - `appsscript.json` も同じように、GitHub の `appsscript.json` の中身で置き換える。
   - Ctrl+S で保存する。
   → 成功：保存してもエラー（赤い帯）が出ない。ファイルが11個（.gs が10個と appsscript.json）並ぶ。
10. 左の歯車「プロジェクトの設定」の一番下「スクリプト プロパティ」→「スクリプト プロパティを追加」で、次の3つを入れて「スクリプト プロパティを保存」。
    | プロパティ | 値 |
    |---|---|
    | `LINE_CHANNEL_ACCESS_TOKEN` | 手順5でコピーしたトークン |
    | `WEBHOOK_KEY` | 自分で決めた英数字20文字くらい（例：`onimaru` のあとに適当な数字や英字）。手順13で使う |
    | `ANTHROPIC_API_KEY` | Claude API のキー（まだなければ後で入れてよい） |
    → 成功：3行が表示される。
11. エディタで `Setup.gs` を開き、上の関数の選択欄で `setup` を選んで「実行」を押す。
    - 「承認が必要です」→「権限を確認」→ 自分のアカウント →「このアプリは Google で確認されていません」と出たら「詳細」→「請求書ボット（タイ）（安全ではないページ）に移動」→「許可」。
    → 成功：下の「実行ログ」に ✅ の行が並ぶ。スプレッドシートに「伝票」「明細」「月次集計」「単価履歴」「品目マスタ」「設定」「ログ」「キュー」のシートができる。
12. エディタ右上「デプロイ」→「新しいデプロイ」→ 左の歯車で「ウェブアプリ」を選ぶ。「次のユーザーとして実行」は「自分」、「アクセスできるユーザー」は「全員」にして「デプロイ」。
    → 成功：「ウェブアプリ」の URL（`https://script.google.com/macros/s/…/exec`）が表示される。コピーする（人に送らない）。

### C. LINE と Apps Script をつなぐ

13. LINE Developers の「Messaging API設定」タブ →「Webhook URL」の「編集」に、手順12の URL の後ろに `?key=` と手順10の WEBHOOK_KEY をつなげたものを入れて「更新」。
    例：`https://script.google.com/macros/s/…/exec?key=onimaru12345`
    「Webhookの利用」をオンにする。
14. 「検証」を押す。
    → 成功：スプレッドシートの「ログ」シートに、区分「検証」の行が増える。
    - LINE の画面に「成功」と出ればそのままでよい。
    - Apps Script は応答を別のアドレスに転送する仕組みのため、LINE の画面ではエラー（302 など）と出ることがある。その場合も「ログ」に「検証」の行が増えていれば、受け取れているので問題ない。
    - 「ログ」に行が増えないときは、URL の写し間違い、または手順12の「アクセスできるユーザー」が「全員」になっていない。
15. 加藤さんの LINE でボットを友だち追加する（LINE Official Account Manager のホーム →「友だちを増やす」→ QRコード）。ボットとのトークで `id` と送る。
    → 成功：ボットが「あなたの userId：U…」と返信する。その `U…` を「設定」シートの M2（報告の送り先ID）に貼る。
16. ボットを八百屋の LINE グループに招待する（業者には事前に伝えておく）。
    → 成功：「ログ」シートに区分「参加」の行ができ、グループIDとグループ名が出る。グループID（`C…`）を「設定」シートの D2（S01 の行のグループID）に貼る。
17. 八百屋さんが次に写真を送ると、「ログ」にその人の「送信者ID」と「送信者名」が出る。その送信者ID（`U…`）を「設定」シートの E2 に貼る。
    - E2 が空欄のあいだは、そのグループの誰が送った写真も読み取る（請求書以外は AI が判定して記録しない）。
    - のりたけファーム（S02）は送信者を空欄のまま（誰でも）にする。グループIDは手順16と同じやり方で D3 に入れる。

### D. 実物の伝票で読み取りを確かめる

18. Google ドライブにフォルダ「テスト伝票」を作り、八百屋の伝票の写真3枚を入れる。フォルダを開いたときのアドレス `https://drive.google.com/drive/folders/XXXX` の `XXXX` をコピーする。
19. スクリプト プロパティに `TEST_FOLDER_ID` ＝ 手順18の `XXXX` を追加する。`ANTHROPIC_API_KEY` が入っているかも確かめる。
20. 別途渡した `InitialData.gs` を、手順9と同じやり方で `InitialData` という名前のファイルとして貼り付けて保存。関数の選択欄で `loadTestAnswers` を選んで「実行」、続けて `loadRefPrices` を「実行」。
    → 成功：「テスト正解」シートに3行、「品目マスタ」の参考単価に数字が入る。
21. `Tests.gs` を開き、`runSampleTest` を選んで「実行」。
    → 成功：実行ログの最初の行が「結果：3／3 件一致」。違うところがあれば、その品目と原因の候補が出る。
    - 1枚ごとに Claude API の料金がかかる。

## コードを直したとき（2回目以降）

1. GitHub の該当ファイルをコピーし、エディタの同じファイルに貼り付けて Ctrl+S。
2. 「デプロイ」→「デプロイを管理」→ 右上の鉛筆アイコン →「バージョン」で「新バージョン」→「デプロイ」。
   → 成功：URL は変わらない（LINE の Webhook URL は直さなくてよい）。
   - 1分ごとの処理（読み取り・記録）は保存しただけで新しいコードになる。Webhook の受け口（doPost）とボタンの処理は、この手順をしないと古いままになる。

## スクリプト プロパティ一覧

| プロパティ | 内容 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE のチャネルアクセストークン（長期） |
| `ANTHROPIC_API_KEY` | Claude API のキー |
| `WEBHOOK_KEY` | Webhook URL の `?key=` の値 |
| `CLAUDE_MODEL` | 省略時 `claude-opus-5-5` |
| `CLAUDE_EFFORT` | 省略時 `medium`。読み取りが不安定なら `high`、時間切れになるなら `low` |
| `SPREADSHEET_ID` `DRIVE_FOLDER_ID` `BOT_USER_ID` | setup() が自動で入れる |
| `TEST_FOLDER_ID` `TEST_SUPPLIER_ID` | runSampleTest() 用（業者は省略時 S01） |
| `IMPORT_FOLDER_ID` `IMPORT_SUPPLIER_ID` | 過去分の一括取り込み importPastFiles() 用 |

## 「設定」シート

- A〜J 列：業者ごとの設定。業者や店舗が増えたら行を足す（コードは直さない）。
  - 送信者ID：空欄なら誰でも。複数はカンマ区切り。
  - 形式：画像／PDF／両方。
  - 既定配送料：配送料の読み間違い（例 150 と 750）を合計から逆算して直すときに使う。
  - VAT率：0 なら VAT の確認をしない。
- L〜N 列：報告の送り先ID、単価変動のしきい値（%）、平均に使う直近件数、検算の許容差、日付のずれの許容（日）。
